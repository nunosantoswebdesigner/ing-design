**ING Design** is a multi-brand design system built by [ING Infinitive](https://github.com/nunosantoswebdesigner).

It solves a specific problem: when you build products for multiple brands, you don't want to rebuild the same Button, Input, or Modal ten times. You want one solid implementation that each brand can make its own — different colours, different corner radius, different typography — without touching the component logic.

## How It Works

Components are built once against the **New York** base theme. Each brand then gets its own theme — a set of CSS variable overrides that change how every component looks without changing how it works.

```
Base component (New York)
├── force8      → orange, sharp corners, bold uppercase
├── myswissski  → red, rounded, clean outdoor feel
└── myicehockey → blue, pill-shaped, modern and fast
```

When you install a component, you get the code — not a package. The shadcn registry model means you own it fully and can customize it per project.

## What's Inside

### Components

Foundational UI primitives — buttons, inputs, dialogs, selects, and more. Each one is:

- Built on **Radix UI** for accessibility out of the box
- Styled with **Tailwind CSS 4** using CSS variables for theme switching
- Documented with live previews, per-brand theme tabs, and one-click code view

### Blocks

Pre-assembled UI sections built from the component library — cards, modals, stat panels, and other patterns you'd otherwise build from scratch on every project.

### Elements

Complex, data-driven components — data tables, charts, calendars, and dashboard widgets. These go beyond simple primitives and are designed to drop into real product pages.

<AccordionItem value="faq-2">
<AccordionTrigger>
How do brand themes work?
</AccordionTrigger>
<AccordionContent>

Each brand theme is a CSS variable override. The base component (e.g. Button in New York) uses variables like `--primary` and `--radius`. A brand theme redefines those variables — sharp orange for Force8, pill-shaped blue for My Ice Hockey — and the component adapts automatically. No code duplication.

</AccordionContent>
</AccordionItem>
